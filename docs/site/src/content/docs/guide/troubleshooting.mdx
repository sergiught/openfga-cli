| Symptom | Resolution |
| --- | --- |
| `connection refused` at `localhost:8080` | Start OpenFGA (see [Quick start](https://github.com/sergiught/openfga-cli/blob/main/README.md#-quick-start)) or select the correct `--profile`/`--api-url`. |
| `no store selected` | Pass `--store-id`, set `OPENFGA_STORE_ID`, or run `ofga profiles set store_id <id>`. |
| The OS keyring is unavailable in a headless container | Mount a secret and use a process-scoped `--auth-*-file` flag. Saved secrets deliberately fail closed rather than entering TOML. |
| Credential cleanup was deferred | Restore keyring access, then run `ofga profiles cleanup-credentials`. Pending exact-field cleanup is stored in the same config file and never deletes a credential still used by a profile. |
| `config changed on disk since it was loaded` | Another process saved first. Re-run the command or reopen the playground to load the newer file. |
| An API or OAuth URL returns a redirect | Configure the final destination URL directly. Redirects are intentionally disabled for credential safety. |
| The playground does not start | It requires an interactive terminal. Use `ofga playground` locally; in CI use a CLI subcommand with `--no-input`. |
| Warning about credentials over HTTP | Use HTTPS for both the OpenFGA API and OAuth token URL. HTTP is only treated as safe for loopback development. |

## Tracing requests with `--debug`

`-d`/`--debug` prints the configuration a command resolved and every API
exchange it makes — method, URL, headers, bodies, status, elapsed time, the
server's `Fga-Request-Id`, and its reported query duration:

```bash
ofga query check user:anne viewer document:roadmap --debug
```

```
DEBU ofga: resolved configuration profile=default api_url=http://localhost:8080 store_id=01ABC… auth=api_token timeout=30s
> POST http://localhost:8080/stores/01ABC…/check
>   Authorization: Bearer ***redacted***
>   {"tuple_key":{"user":"user:anne","relation":"viewer","object":"document:roadmap"}}
< 200 OK  (12ms, server 3ms, request-id 1J9…)
<   {"allowed":true}
```

This answers the questions a one-line error cannot: which profile and store the
command actually resolved to, whether a retry happened and how many, whether
time was spent in the network or in the server, and exactly what the server was
sent and returned.

The trace goes to **stderr**, so `--debug` composes with `--json` and friends
without corrupting piped output:

```bash
ofga stores list --json --debug 2>trace.log | jq '.[].id'
```

Credentials are redacted before anything is printed: `Authorization` and cookie
headers, secret-named JSON and form fields, and URL query values are masked, and
OAuth token-fetch requests are never captured at all. A trace is safe to paste
into a bug report, though it is worth a glance first — tuple and object names
are your data.

## Shell completion

```bash
# bash
source <(ofga completion bash)
# zsh
ofga completion zsh > "${fpath[1]}/_ofga"
# fish
ofga completion fish | source
# PowerShell
ofga completion powershell | Out-String | Invoke-Expression
```

Completion is **dynamic**: `--profile`, `--store-id`, and `--model-id` (and the matching positional args) complete real profile names, store IDs, and model IDs from your server. Network-backed completions are bounded by a short timeout so they never hang your shell.
