`ofga` is built to compose:

- `--json` emits clean, machine-readable JSON (secrets omitted) for `jq`.
- `-o jsonl` emits compact JSON Lines: a list result becomes one object per line (nothing at all when it is empty) and any other result is a single line. It streams, so it suits `while read` loops, and `tuples read -o jsonl` writes a file that `tuples write --file` takes back as is:

  ```bash
  ofga tuples read -o jsonl > tuples.jsonl
  ofga tuples write --file tuples.jsonl
  ```

- `--yaml` (or `-o yaml` / `--output yaml`) emits the same structured data as YAML, for tools that prefer it (e.g. diffing against a YAML-based config).
- `--plain` emits unstyled TSV for both reads and mutations; embedded tabs,
  newlines, and control characters are normalized to spaces so every item
  remains one record. Key/value results are `key<TAB>value`, so
  `query check --plain` prints `allowed<TAB>true` or `allowed<TAB>false`
  (a denied check is still a successful query, so the exit code stays `0`).
- Meaningful **exit codes**: `0` success, `1` generic failure, `2` usage error, `3` failed tests — `model test` (or its coverage gate) and `assertions test` — `4` network error, `130` interrupted by Ctrl-C/SIGINT.
- First-class server mutation commands support `-n`/`--dry-run`; `ofga api` is an expert escape hatch.
- Destructive replacements and deletes prompt on a TTY and require `--force` when non-interactive, so scripts fail safe.
- Piped output drops colors and box-drawing automatically.
- `--timeout` bounds each HTTP request (30 seconds by default; `0` disables it).
- `--no-input` prevents prompts and disables the bare-command TUI for automation running under a pseudo-TTY.
- A downstream consumer that closes stdout early (for example `| head`) is
  treated as normal pipeline completion unless a command-specific failure must
  take precedence.
- `ofga api --plain` preserves the response body bytes rather than
  pretty-printing JSON, adding only a missing final newline.

Bulk tuple writes/deletes are sent in server-sized batches and are not
transactional across batches. A rejected batch no longer aborts the run: the
remaining tuples are still attempted, and JSON/YAML and plain output report
`written`/`deleted`, `total` and `complete: false` before the command exits
non-zero. JSON/YAML output additionally carries a `successful` array of tuples
and a `failed` array of `{tuple, reason}` objects; `--failed-file <path>` writes
the failed tuples on their own, in the input's format, ready to re-run.
Automation should inspect the exit status and treat the reported count as
already committed.

> **Note:** `ofga tuples read`, `ofga tuples changes`, `ofga stores list`, and
> `ofga model list` auto-paginate and return **all** rows by default
> (`--page-size` only sets the per-request page size, not a total cap). Against
> a large store that can be a lot of output: cap it with `--max-results`
> (alias `--limit`), or pipe through `head` or `--json | jq`.

## Errors as JSON

With `--json`, `--yaml` or `--jq` (or `-o json|jsonl|yaml`), a command that fails
writes exactly one line of compact JSON to stderr, always JSON even under
`--yaml`, and nothing else from the error path: no `●` line and no hints. The
exit code is unchanged. `--quiet` does not suppress it.

```json
{"error":{"code":"not_found","message":"GET /stores/01H…: 404 store_id_not_found store not found","status":404,"api_code":"store_id_not_found","hint":"…","details":[]}}
```

| Field | Meaning |
| --- | --- |
| `code` | Stable category, see the table below. Branch on this, not on `message`. |
| `message` | The human message, first line. |
| `status` | HTTP status. Only present when the error came from an API response. |
| `api_code` | OpenFGA's own error code. Only present when the server sent one. |
| `hint` | The suggested remediation, when there is one. |
| `details` | Array of objects, always present and possibly empty: unknown-command `suggestion`s, an underlying `cause`, and per-command extras. |

| Code | When | Exit code |
| --- | --- | --- |
| `usage` | Unknown command or flag, wrong arguments, invalid `--jq` or `-o` | 2 |
| `confirmation_required` | A destructive command ran non-interactively without `--force` | 1 |
| `validation` | The server rejected the request as invalid (400) | 1 |
| `already_exists` | A tuple write duplicated an existing tuple | 1 |
| `unauthenticated` | Missing, invalid or rejected credentials (401) | 1 |
| `forbidden` | Authenticated but not allowed (403) | 1 |
| `not_found` | The store, model or other resource does not exist (404) | 1 |
| `rate_limited` | The server throttled the request (429) | 1 |
| `server` | The server failed (5xx) | 1 |
| `network` | The server could not be reached | 4 |
| `test_failed` | `model test`, `assertions test` or a coverage gate failed | 3 |
| `partial_failure` | A bulk write/delete or `mappings apply` finished with some failures. When the server became unreachable partway, the code is `network` and the exit code 4 | 1 |
| `canceled` | Interrupted by Ctrl-C or SIGTERM | 130 |
| `error` | Anything else, including a config file that will not load | 1 |

## Agent mode

When a coding agent drives `ofga`, it defaults to output that is cheap to parse
and never waits on a human. Agent mode turns on when any of these holds, checked
in this order:

1. `--agent` (or `--agent=false` to force it off).
2. `OPENFGA_AGENT_MODE=1` (or `=0` to force it off).
3. A detector variable set to `1`: `CLAUDECODE` (Claude Code) or `GEMINI_CLI` (Gemini CLI).

While it is on:

- Output defaults to compact one-line JSON. An explicit `--plain`, `--yaml` or
  `-o table|plain` still wins, and `--json` stays compact.
- Prompts are off (`--no-input`) and color is off.
- Success messages (`created store …`) are dropped; warnings and errors are kept.
- Failures print the [JSON error envelope](#errors-as-json) on stderr.
- The TUI and the playground refuse to start, with a usage error (exit code 2),
  so a bare `ofga` never hangs an agent.

Set `OPENFGA_AGENT_MODE=0` to opt out. This matters for one known trade-off:
a command you run yourself through an agent's `!` shell escape inherits the
detector variable too, so it gets JSON output unless you opt out.

To see what was decided and why, run `ofga version --json` and read
`agent_mode` (`enabled` and `reason`).

## Extracting fields without jq

`--jq` filters machine-readable output through a built-in jq engine, so a
container image carrying only `ofga` can still pull a field out:

```bash
STORE_ID=$(ofga stores create my-store --jq '.id')
ofga stores list --jq '.[] | select(.name=="prod") | .id'
ofga tuples read --jq 'length'
```

It implies `-o json`, so it does not need to be combined with `--json`. String
results print bare (like `jq -r`) so they can be captured straight into a shell
variable; every other type prints as compact JSON, one result per line. An
invalid filter is rejected before any request is made.

Because a filter such as `length` or `sort_by(.x)` has to see the whole
document, `--jq` buffers output that would otherwise stream — worth remembering
when filtering a very large `tuples read`.

## Discovering commands

`ofga commands` prints a catalog of every runnable command: its path, usage,
flags, examples, and whether it needs a store or model, mutates state, supports
`--dry-run` or only runs interactively. Global flags are listed once. It works
offline and needs no profile.

A command is marked `mutates` when it changes server state (stores, models,
tuples, assertions), local CLI config or files in the working tree (such as
`model test init` scaffolding). An output file you name with a flag such as
`--output-file` or `--cursor-file` doesn't count.

`requires_store` and `requires_model` mean the command resolves the ID from
`--store-id` or `--model-id`, the environment or the profile, and fails without
one. An ID the command takes as a positional argument, as in
`ofga model get <model-id>`, shows in its `usage` instead.

```sh
# Every command that changes state
ofga commands --json | jq -r '.commands[] | select(.mutates) | .path'
```

## Sending extra request headers

Deployments that put OpenFGA behind a gateway with its own header-based
authentication can add headers per request or per profile:

```bash
ofga stores list --header 'X-Scope-OrgID: tenant-7'
```

```toml
# ~/.config/ofga/config.toml
[profiles.prod]
api_url = "https://openfga.internal"
headers = ["X-Scope-OrgID: tenant-7"]
```

A `--header` flag adds to the profile's headers, and repeating a name replaces
it rather than sending it twice. Headers are sent only to the OpenFGA API — the
OAuth token endpoint is deliberately excluded, so a gateway credential is never
forwarded to your identity provider. `Authorization` cannot be set this way
(the API client owns it); use the profile's auth settings or `--auth-token-file`.

## Exporting a large store

`ofga tuples read` streams its output, so memory stays flat no matter how many
tuples match — rows appear as they arrive instead of after the last page. Use
`--output-file` to send the tuples to a file and leave the terminal free for
progress, which is reported every 50,000 tuples with a running rate:

```bash
ofga tuples read --output-file tuples.json
# read 50000 tuples, 18432/s
# read 100000 tuples, 18510/s
```

The file is JSON unless `--yaml` or `--plain` is given, and JSON round-trips
straight back in:

```bash
ofga tuples write --file tuples.json
```

The styled table is the one format that cannot stream — column widths are not
known until the last row — so it still buffers. For a large export use `--json`,
`--plain` or `--output-file`.

## Following the changelog

`ofga tuples changes` can resume where a previous run stopped, which is what a
polling job wants instead of re-reading the changelog from the beginning:

```bash
# First run records where it got to.
ofga tuples changes --json --token-file .fga-cursor > changes.json

# Later runs pick up from there.
ofga tuples changes --json --continuation-token "$(cat .fga-cursor)" \
  --token-file .fga-cursor > new-changes.json
```

`--token-file` is written before the changes are rendered, so a consumer that
exits early (`| head`) still leaves a usable cursor behind. Stopping early with
`--max-results` records the token that produced the partial page, so resuming
replays those changes rather than skipping them. The JSON output itself stays a
bare array.

```bash
# Which documents can anne view?
ofga query list-objects document viewer user:anne --plain

# Fail a CI job if the assertion suite regresses
ofga assertions test || exit 1
```
