Read an identity provider's current state, replay it through a mapping file, and write the resulting tuples to the active profile's store. With no file argument it uses ./mapping.yaml.

The read comes back as snapshot events, one per user, organization, membership and so on, which the mapping's rules handle like live events. A rule takes part when its `when` also names a snapshot type, such as `input.type == "snapshot.organization.member"`; a mapping with none has nothing to backfill, and the error suggests the clause for each rule. Only the types the mapping names are read.

backfill reads the provider, then the store, and writes only the tuples the store lacks. On a large store it reads only the objects the mapping writes to. It never deletes, and a tuple that is already there with a different condition is left for drift to replace. It shows the tuples it would write and asks before writing (--force skips the question, --dry-run stops after showing them). The provider is read once, so the tuples reflect it as of that moment. Changes made while the command runs, or after it, are not included. Use `ofga mappings drift` to compare the store with the provider and to remove tuples the provider no longer backs.

Run again after a failure: tuples that already landed are not written twice. Auth0 needs a machine-to-machine application. Above 1,000 users the read uses Auth0's user export job, which needs no extra scope. --since 2h (or an RFC 3339 time) reads only the Auth0 users changed since then, at most 1,000; other types are still read whole.

Exit codes: 0 ok · 1 error · 2 usage · 4 network · 130 interrupted.

## Usage

```sh
ofga mappings backfill [file] --provider <name> [flags]
```

## Examples

```sh
# See what a backfill from Auth0 would write
ofga mappings backfill auth0.yaml --provider auth0 --dry-run

# Read only the users changed in the last two hours
ofga mappings backfill auth0.yaml --provider auth0 --since 2h --force

# Write it without the prompt, in a script
ofga mappings backfill auth0.yaml --provider auth0 --auth0-client-secret-file ./secret --force
```

## Flags

| Flag | Description | Default |
| --- | --- | --- |
| `--auth0-client-id` | Auth0 machine-to-machine client ID (else $AUTH0_CLIENT_ID) |   |
| `--auth0-client-secret-file` | file holding the client secret (else $AUTH0_CLIENT_SECRET) |   |
| `--auth0-domain` | Auth0 tenant domain (else $AUTH0_DOMAIN) |   |
| `--auth0-tenant` | tenant name for display (default: the first label of the domain) |   |
| `-n, --dry-run` | show the tuples without writing anything | `false` |
| `-f, --force` | write without asking | `false` |
| `--provider` | identity provider to read (auth0) |   |
| `--since` | read only what changed since a duration ago (2h) or an RFC 3339 time; users only |   |
