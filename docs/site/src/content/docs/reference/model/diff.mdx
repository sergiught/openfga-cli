Compare two authorization models and classify what changed.

Each argument is a model file (DSL or JSON), '-' for stdin, 'store' for the active store's latest model, or a model ID in the active store. With one argument the old side is the store's latest model, so `ofga model diff model.fga` shows what would change if you wrote that file.

Breaking changes can make previously valid tuples or checks stop working: removed types, relations, directly related user types and conditions, or condition parameters that were removed or changed type. Changed lists differences that alter behavior without removing anything, such as a rewritten relation definition or a changed condition expression. Added lists new types, relations, user types and conditions.

Cost compares the per-user-type weights of each relation (see `model optimize`); an increase means checks on that relation can need more work. A weight of -1 in --json/--yaml output means unbounded; human output renders it inf.

Exit codes: 0 no breaking changes · 1 error · 2 usage (including an invalid model) · 3 a breaking change was found, or, with --fail-on-cost, a cost increase · 4 the server was unreachable.

## Usage

```sh
ofga model diff <old> [new] [flags]
```

## Examples

```sh
  ofga model diff model.fga
  ofga model diff old.fga new.fga
  ofga model diff store model.fga --fail-on-cost
  ofga model diff 01H… store
```

## Flags

| Flag | Description | Default |
| --- | --- | --- |
| `--fail-on-cost` | exit 3 when any relation got more expensive, not only on breaking changes | `false` |
| `--report` | write a report in this format ("github" annotations); to --report-file if set, otherwise printed to the terminal |   |
| `--report-file` | path to write the --report file to (requires --report) |   |
